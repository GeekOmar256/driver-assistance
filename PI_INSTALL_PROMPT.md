# Prompt for the AI connected to the Pi: Tkinter edition

Install and run the native Tkinter VisionGuard GUI on the screen connected to the Raspberry Pi. Execute the work and report actual results.

1. Inspect board, `/etc/os-release`, architecture, Python version, free space and the graphical desktop session. Raspberry Pi 5 with ARM64 Debian 13 Trixie/Python 3.13 is permitted, as are 64-bit Raspberry Pi OS Bookworm/Trixie. Do not reimage or upgrade the OS. Identify the logged-in desktop user and its display session; run the GUI as that user, not root. Do not bypass display authorization with `xhost +`. If no graphical session exists, install and validate dependencies but report that launching the GUI awaits a desktop session.
2. Install Git if missing. Clone `https://github.com/GeekOmar256/driver-assistance.git`, branch `codex/raspberry-pi-tkinter`, into `~/visionguard-tkinter`. Preserve existing checkouts and user changes; inspect remote, branch and status before reusing a folder. Read README.md. Record the commit.
3. Run `bash scripts/install-tkinter-pi.sh`. This installs Tk and FFmpeg, then the existing ARM CPU inference environment, models/checksums and tests. Use the project venv; no global pip, CUDA, API keys or substitute weights. Diagnose actual dependency errors before retrying; do not build large packages from source unattended.
4. Discover USB cameras with `v4l2-ctl --list-devices`. For CSI, check configured repositories for rpicam tools and python3-picamera2. Use `picamera2` only when that stack is available; otherwise continue using USB or a local video. Do not add external apt repositories.
5. From a terminal on the Pi graphical desktop run `bash scripts/run-tkinter-pi.sh`. Verify three tabs: Driver alerts first, Video / Live second, Settings third. Verify standard two-stage is selected by default, person is enabled, and all four methods are selectable with corresponding class lists.
6. In Settings choose a video, camera (`0`, `/dev/video2`, or `picamera2`) or a real RTSP/HTTP stream URL; Apply settings and Start. Confirm annotated frames on Video / Live and detection continues on Driver alerts. Test people and signs/lights using available footage; confirm large directional alerts, brief-alert retention, confidence filtering, class deselection, Stop, Pause/Resume, model switching and resizing/fullscreen. Do not report detections from synthetic blank footage as successful recognition.
7. Verify directional audio through the connected screen/speaker. Use the OS audio output selector if necessary. Report unavailable audio/camera/footage or stream access. Keep the GUI running for the user. No autostart or firewall changes are requested.
8. Return installation directory, commit, OS/Python and library versions, test/checksum results, actual input and display/audio used, start/stop instructions and remaining errors. Never claim unperformed hardware tests passed.
