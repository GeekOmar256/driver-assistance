# Prompt for the AI connected to the Raspberry Pi

Install and validate VisionGuard on the Raspberry Pi you can access. Execute the steps on the Pi; do not just describe them.

1. Identify the board, OS and CPU architecture with `tr -d '\0' </proc/device-tree/model`, `cat /etc/os-release`, `uname -m`, `dpkg --print-architecture`, `python3 --version` and `df -h "$HOME"`. The target is Raspberry Pi 5 with 64-bit Raspberry Pi OS Bookworm or Trixie, or Debian 13 Trixie (`aarch64` / `arm64`). Debian GNU/Linux 13 with Python 3.13 is explicitly permitted: continue installation even if the OS name does not say Raspberry Pi OS. Compatibility must be confirmed by installation and runtime checks. If it is 32-bit or outside those targets, report what you found before making system changes. Do not reimage or upgrade the OS.
2. If Git is missing, run `sudo apt-get update && sudo apt-get install -y git`. Clone the public deployment branch with `git clone --single-branch --branch codex/raspberry-pi https://github.com/GeekOmar256/driver-assistance.git ~/visionguard-pi`. If that folder exists, check its remote, branch and working tree first. Preserve user changes; use a fresh directory if the existing checkout differs. Record `git rev-parse HEAD`.
3. From the checkout, read `README.md` and run `bash scripts/install-pi.sh`. This installs OS libraries, creates the project's `.venv`, installs ARM CPU PyTorch and torchvision and the web dependencies, verifies both bundled checkpoints, and runs regression and inference checks. Do not use system-wide pip, install CUDA, ask for an API key, or download substitute weights. If installation fails, capture the actual error, diagnose it for the installed OS/Python, and retry only after identifying the cause.
4. Detect the camera type. For USB, run `v4l2-ctl --list-devices` and select the correct device, e.g. `VISIONGUARD_CAMERA=/dev/video2`. For CSI, first check whether `rpicam-hello` and `python3-picamera2` are available from the configured OS repositories. If available, run `rpicam-hello --list-cameras`, install `sudo apt-get install -y python3-picamera2` if needed, and use `VISIONGUARD_CAMERA=picamera2`. Plain Debian may lack the Raspberry Pi camera stack; if unavailable, continue software validation with USB or an uploaded video and report CSI testing as pending. Do not add external apt repositories or replace the OS to obtain camera packages. If no camera is connected, validate using an uploaded local video and report that live camera testing is pending.
5. Run `bash scripts/run-pi.sh` as the normal user with the chosen camera environment variable. Keep it bound to `127.0.0.1:5000`. Verify `curl -fsS http://127.0.0.1:5000/api/models` lists four available methods and `curl -fsS http://127.0.0.1:5000/api/classes` includes `person`. If a remote browser is needed, use an SSH tunnel rather than exposing the server. Do not enable autostart or change firewall rules without my request.
6. Open the UI at `http://127.0.0.1:5000`. Confirm the default is the standard two-stage mode, `person` appears in the class list, and Auto is 640. Use a local video showing people and, if possible, signs and traffic lights. Enable sound and verify a detected person produces a directional visual and spoken alert. Separately test the connected camera if present. Report what actually worked, including any unavailable browser, audio device, footage or camera. Keep the server running in your session for me to try.
7. Return the installed directory, Git commit, OS/Python and library versions, checkpoint and test results, camera device/backend, URL, and exact start/stop commands. Report any remaining problems with the relevant error lines.
